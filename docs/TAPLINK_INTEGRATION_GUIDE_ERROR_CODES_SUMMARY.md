# Taplink 集成指南错误码整理归纳

## 概述

本文档整理归纳了《Sunbay Taplink SDK for Android - 集成指南》中提到的所有错误码，按照错误类型、处理策略和重试机制进行分类整理。

## 幂等性机制与重试策略

### 核心原则

1. **特殊错误码**（T34、T38、T39、000）重试时，必须使用**新的** `transactionRequestId`
2. **其他所有错误码**重试时，可以使用**相同的** `transactionRequestId`
3. 修改金额或订单后，必须使用新的 `transactionRequestId`

### 详细重试规则

#### 必须使用新ID的错误码

| 错误码 | 说明 | 处理方式 |
|--------|------|----------|
| T38 | host交易拒绝 | 必须使用**新** `transactionRequestId` |
| T39 | Host交易处理中 | 必须使用**新** `transactionRequestId` |
| 000 | 交易成功 | 无需重试 |

#### 特殊处理：响应超时（T34）

| 错误码 | 说明 | 处理方式 |
|--------|------|----------|
| T34 | Tapro响应超时 | 先查询交易状态，确认结果后再使用**相同** `transactionRequestId` 重试 |

#### 可以使用相同ID的错误码

| 错误码类型 | 典型错误码 | 说明 |
|------------|------------|------|
| **响应超时** | T34 | 先查询交易状态，确认结果后可使用相同ID重试 |
| **交易锁定** | T27, T30, T31 | 系统正在处理其他交易，可使用相同ID重试 |
| **连接错误** | T06, T07, T03, T04, T05 | 连接问题，可使用相同ID重试 |
| **初始化错误** | T01, T02, T14 | 配置问题修复后，可使用相同ID重试 |
| **参数错误** | T15, T16, T17, T18, T19, T28 | 参数错误修复后，可使用相同ID重试 |
| **数据传输错误** | T21, T22, T23, T24 | 传输问题，可使用相同ID重试 |
| **USB/串口错误** | T10, T11, T12, T13, T35, T37 | 硬件问题修复后，可使用相同ID重试 |
| **其他错误** | 除T38/T39/000外的所有错误码 | 可使用相同ID重试 |

## 错误处理最佳实践

### 1. 错误码判断逻辑

```kotlin
/**
 * 判断是否可以使用相同的 transactionRequestId 重试
 * 
 * 特殊错误码（T34、T38、T39、000）必须使用新ID
 * 其他所有错误码都可以使用相同ID
 */
private fun canRetryWithSameId(code: String): Boolean {
    // T34、T38、T39、000 不能使用相同ID
    return code !in listOf("T34", "T38", "T39", "000")
}
```

### 2. 错误处理策略

```kotlin
fun handlePaymentError(error: PaymentError) {
    when (error.code) {
        // 特殊错误码：必须使用新ID
        "T34" -> {
            // 响应超时：先查询状态
            queryTransactionStatus()
        }
        "T38" -> {
            // host交易拒绝：必须使用新ID
            showError("交易被拒绝，请使用新的交易请求ID重试")
        }
        "T39" -> {
            // Host交易处理中：必须使用新ID
            showError("交易处理中，请查询状态或使用新ID重试")
        }
        
        // 初始化错误：需要修复
        "T01", "T02", "T14", "T20", "T25", "T41" -> {
            showError("初始化错误：${error.message}")
        }
        
        // 连接错误：可重试
        "T03", "T04", "T05", "T06", "T07", "T10", "T11", "T12", "T13", "T35", "T37" -> {
            showError("连接错误：${error.message}，可重试")
        }
        
        // 参数错误：修复后可重试
        "T15", "T16", "T17", "T18", "T19", "T28" -> {
            showError("参数错误：${error.message}，请检查参数")
        }
        
        // 交易处理错误：可重试
        "T27", "T30", "T31", "T40" -> {
            showError("交易处理错误：${error.message}，可重试")
        }
        
        // 其他错误：可使用相同ID重试
        else -> {
            retryWithSameId()
        }
    }
}
```

### 3. 超时处理（T34）

```kotlin
private fun handleTimeout(transactionRequestId: String) {
    // 先查询交易状态
    queryTransactionWithPolling(transactionRequestId) { result ->
        when (result.transactionStatus) {
            "SUCCESS" -> {
                // 交易成功，无需重试
                handleSuccess(result)
            }
            "FAILED" -> {
                // 交易失败，可使用相同ID重试
                retryWithSameId()
            }
            "PROCESSING" -> {
                // 仍在处理中，继续查询
                continuePolling()
            }
        }
    }
}
```

## 总结

1. **错误码总数**：集成指南中共定义了 **42个** T系列错误码 + **1个** 成功码（000）
2. **重试策略**：只有 **3个** 错误码（T38、T39、000）需要特殊处理，其余都可使用相同ID重试
3. **特殊处理**：T34（响应超时）需要先查询交易状态再决定重试策略
4. **幂等性保证**：通过 `transactionRequestId` 实现，确保相同ID的交易不会重复处理

这套错误码体系为开发者提供了清晰的错误处理指导，特别是在幂等性和重试策略方面提供了明确的规则。
